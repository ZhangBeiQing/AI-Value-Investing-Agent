# fixed_tracked 个股共同分析规则（无限制实验版）

## 适用范围

本文件与 `investment_policy.md`、`configs/research/web_research_policy.md` 一起生成 `03_stock_analysis_input.md`，供 Bull、Bear、Juror 和 finalizer 共同读取。

`investment_policy.md` 是角色定位、投资哲学和交易纪律的单一来源；本文件只补充逐股研究方法，不重复定义另一套投资风格。角色的具体职责和输出格式以各自的 Skill reference 为准。

`web_research_policy.md` 是搜索入口、来源分级和证据准入的单一来源；本文件只定义 fixed_tracked 在什么情况下必须联网，不重复维护来源黑白名单。

## 共同研究方法

### 证据与推断

- 明确区分已核实事实和基于事实的推断。
- 理由中直接写清事实发生日期、来源、推断链条和关键不确定性。
- 发现本地材料相互冲突时，应先核对原始来源，无法解决时保留冲突并降低结论置信度。
- 不得为了使论证完整而编造精确目标价、估值倍数、订单数字或收益率。

### 公司质量与风险检查

- 检查盈利可持续性、护城河、资本回报、资产负债表、现金流、治理和股东回报。
- 历史价格区间、历史 PE/PB 和当前估值只是判断素材，不是自动买卖锚。
- 强周期公司必须检查当前盈利是否接近周期顶部，不能只用当期高利润推导长期低估。

### 估值与交易判断

你可以自由使用任何估值方法（历史均值、情景估值、趋势分析、综合判断），不设框架准入限制。你的买卖决策完全自主——不设仓位上限、止损线或分批节奏规则。唯一要求是决策必须基于你给出的理由。

### 持仓与投资逻辑记忆

研究包中的历史部分不是完整交易记录，而是由 Python 从完整历史中生成的研究记忆视图。完整历史仍保存在本地，研究记忆只保留：

- 最后一次投资逻辑总结；
- 上轮遗留的待核验事项。

历史 `recommended_action`、`price_target`、计划性操作条件和 `verdict` 不会进入本轮 Prompt。历史 verdict 无论新旧都可能造成结论锚定；不要自行打开原始历史文件把这些内容重新读回来。

使用投资记忆时应重新检查：

1. 当时买入、卖出或继续持有依赖的核心事实今天是否仍成立；
2. 今天是否出现新的反证或此前不知道的重要事实；
3. 当前结论来自今天的证据，还是只是在复述历史判断。

投资记忆用于保持长期逻辑连续性，不是要求今天重复历史动作。历史总结中的 `action_type` 和 `action_num` 不进入研究包；当前真实持仓以当天组合输入为准。

## 财报时间与时效

对 A 股重点检查：

- 1 月：年报预告窗口；
- 4 月：年报和一季报密集披露；
- 7 月至 8 月：中报窗口；
- 10 月：三季报窗口。

距离关键财报或经营披露窗口不足 15 天且股价走弱时，应提高财报验证风险，但没有公司公告、财报数据或高可信证据时，不得预设业绩不及预期。港股和 ETF 按对应市场与标的特性判断。

## 盈利推演（鼓励但不强制）

鼓励利用分析日之前已经公开的信息推演下一季度和未来六至十二个月的收入、利润和关键经营趋势。公司高频经营披露、产业链交叉验证、量价与市场计价都是有用的信息源。

如果你认为已有信息足以推演，请建立"量 × 价/结构 → 收入 → 毛利率 → 费用及特殊项 → 净利润"的桥接，输出方向或 Bear/Base/Bull 区间，并与机构一致预期、当前估值和股价已计入程度比较。

如果你认为已有信息不足以推演，可以直接说明哪些未知项需要等待财报，并基于现有信息形成判断。不确定时可以给更宽的情景区间、更低的置信度——但不能因为"财报还没发"就停止分析或只输出 HOLD/FLAT。

## 本地材料与联网补证

先完整读取当天共同输入和当前股票研究包，再决定搜索范围。不要用联网搜索替代本地研究包。

命中以下任一情况时必须联网补证：

1. 研究包_research.md中 `上轮遗留待核验事项` 有今天应核验的遗留事项；
2. 今日或最近一个交易日大涨大跌、明显放量，但本地新闻、公告和财报不能解释；
3. 研究包中的新闻、公告、经营数据明显滞后、缺失、未知或相互矛盾；
4. 准备支持 `BUY` 或 `SELL`，而关键依据依赖可能已经变化的外部事实；
5. 不联网就无法区分普通高波动和新的基本面或事件驱动。

搜索方法和来源能否进入论据，严格服从同一份 `web_research_policy.md`。百炼只负责召回候选来源，不代表搜索结果已经通过证据准入。

联网得到的新证据必须写入对应理由、事实或推断，包括事件日期及其如何改变判断。最终辩论 JSON、stock verdict 和决策文件禁止写 URL、Markdown 链接、脚注或常规来源引用。只有雪球、股吧、社交媒体传闻等低可信信息确实影响判断时，才标注"低可信来源"或"未经证实"及其影响，仍不得展示来源名称、标题或 URL。

## 动作语义

合法动作只有：

```text
BUY / SELL / HOLD / FLAT
```

- `BUY`：下一交易日确实准备增加持仓，`action_num` 必须是可执行的正整数。
- `SELL`：下一交易日确实准备减少持仓，`action_num` 必须是可执行的正整数且不能超过持仓。
- `HOLD`：当前有持仓但下一交易日不交易，`action_num=0`。
- `FLAT`：当前无持仓且下一交易日不交易，`action_num=0`。

A 股普通股票数量默认按 100 股取整；港股和 ETF 按标的交易单位执行，输入未知时应在最终建议中注明"待执行层确认"。

若最终动作是 `HOLD` 或 `FLAT`：

- 可以在 `recommended_action` 中说明未来价格或事实条件下的交易设想；这些条件预案不改变本次零交易数量，也不会自动执行，实际交易仍须经过下一次决策；
- 不应因为没有交易而省略完整判断。

若最终动作是 `BUY`：

- 自主决定买入数量、目标仓位及一次或分批执行方式，不设最低首批比例；
- 说明数量依据、可用现金、执行后仓位及你认为重要的组合风险；如有后续计划，说明相应条件。

若最终动作是 `SELL`：

- 自主决定卖出数量及一次或分批执行方式，说明数量依据及执行后仓位；
- 根据需要说明不同市场情况及后续交易条件，不强制套用固定执行模板。

`recommended_action` 是本次分析后下一个交易日的执行预案，可以详细说明高开、低开、盘中变化、执行数量和分批方式。它会永久保存在历史记录中，但不会被重新注入下一轮研究 Prompt。需要跨越多个交易日的长期逻辑必须写入事实、推断、`court.verdict` 或风险条件，不能依赖旧的 `recommended_action` 自动续期。

`next_day_watchlist` 只记录下一轮需要核验的问题。可以记录需要观察的价格、量能、公告、财报、行业或宏观事实，但不得写成"满足某价格便买入、卖出或加仓"的执行指令。需要记录多少项由当前股票的实际未决问题决定，不设固定数量。

## 辩论后的价格印象

Bull 和 Bear 只提供估值、安全边际、盈利质量和周期位置论据，不输出最终价格标签。

每名 Juror 在读取原始证据和完整辩论后，独立输出自己的 `price_impression`，并在 ballot 的 `reason` 中解释价格判断和交易动作之间的关系。

Python 只保存三名 Juror 的价格印象，不计算多数、中位数或最终标签。finalizer 比较三名 Juror 使用的事实、盈利假设、估值口径、周期判断和来源质量后，形成最终 `price_impression`。finalizer 不得根据已锁定的 `action_type` 反推价格印象，也不得用价格印象覆盖交易动作。

合法值：

```text
明显低估 / 偏低估 / 合理偏低估 / 合理 / 合理偏贵 / 偏贵 / 明显高估 / 泡沫
```

价格印象应综合盈利质量、盈利增速、历史估值、历史价格分布、行业景气、宏观环境、催化和量价，不使用单一 PE/PB 机械决定。
