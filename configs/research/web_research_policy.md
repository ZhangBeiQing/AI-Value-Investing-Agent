# 联网搜索与证据规则

## 一、按运行环境选择搜索入口

搜索入口是优先级建议，不再强制所有环境只用百炼：

- **Codex + GPT 模型**（同时满足）：优先使用 Codex / GPT 自带的联网搜索能力，例如 `web.run` / `search_query`，按会话实际暴露的工具名调用。Codex 不应仅因为仓库配置了百炼 MCP 就优先调用百炼。
- **其他运行环境或模型组合**：优先使用阿里云百炼搜索 MCP；DeepSeek Harness 常见工具名为 `mcp__bailian__bailian_web_search`，OpenCode / Claude Code 常见为 `WebSearch`（百炼 MCP），以当前会话实际能力为准。
- 首选工具不可用时，可使用当前会话已提供且可用的另一搜索入口（内置搜索或百炼 MCP）；无需仅因切换这两个入口再次请求确认。不得自行拼接爬虫或第三方检索 API。
- DeepSeek Harness 曾停用的 `web_search` 不视为可用的内置入口；不得仅凭工具名字推定能力可用，也不得把百炼 MCP 称为 Codex 内置搜索。

如果上述可用搜索入口均不存在、被禁用或调用失败：

- 记录 `search_status = web_search_unavailable`；
- 停止依赖外部搜索的角色并报告原因，不用模型记忆冒充联网核验；
- 用户另有明确工具偏好时按用户指示执行。

“搜索成功但无结果”“只有低等级来源”和“工具不可用”必须区分。无论入口为何，搜索只负责候选来源召回，需要核对原文时按运行时的抓取边界打开公告、交易所文件或原始页面。来源准入、回测日期截断和原文核验标准保持一致。

## 二、搜索与原文阅读分工

```text
按运行环境选择的搜索入口
→ 发现候选来源和后续检索关键词

打开具体网页或 PDF
→ 核对选中的公司公告、交易所文件、协会数据、正式研报或原始页面
```

搜索结果的排序、来源数量和摘要语气都不代表可信度。搜索摘要只能用于发现线索，不能单独支持财务数字、订单、客户、产能、正式指引、关键预期或交易结论。

搜索应围绕明确问题，并尽量加入来源锚点，例如公司名称、证券代码、公告类型、投资者关系、交易所或目标机构。宽泛搜索只用于发现线索；发现线索后必须继续追溯原始来源。

## 三、来源分级与证据准入

### 3.1 来源等级

按以下顺序选择来源：

1. **A 级：** 公司公告、财报、交易所和监管文件；
2. **B 级：** 公司业绩会、投资者关系记录、政府、行业协会，以及客户、供应商和竞争对手的正式披露；
3. **C 级：** 正式卖方研报、持牌财经媒体的独立采访或调查；
4. **D 级：** 百家号、其他身份不明的自媒体、内容农场、聚合转载和无法识别原始出处的内容。

**关于卖方研报的定位：** 研报列入 C 级，只代表"署名可追溯的机构观点"，**不代表其中的事实陈述可信**。国内研报普遍存在发布滞后、报喜不报忧、跟随股价调整评级、把公司口径照抄成行业结论等问题。因此：

- 研报的**观点、目标价、盈利预测**只作为"市场预期与立场"的记录使用，用于判断预期差和一致预期的位置，**不能当作事实**；
- 研报引用的数字（产能、订单、份额、价格、客户）必须回溯到 A/B 级原始披露或独立第三方数据，回溯不到就标注"仅研报口径"；
- 研报与本条规则冲突时，以 A/B 级一手资料为准，不因为"是券商写的"而提高等级。

**权重总原则：** 在**可核验程度相同**的前提下，一手观察（公司披露、产业一线从业者的具体事实描述）优先于二手的机构推论。机构研报的价值在"记录市场怎么想"，不在"告诉我们事实是什么"。

### 3.2 特殊来源：雪球、股吧等投资社区

雪球、股吧、投资者论坛等投资社区不按普通 D 级来源处理，因为它们有独特的双重属性：

**有价值的一面：** 这些平台上确实经常有行业内人士、从业人员和各行各业的大佬出没，有时会出现提前爆料、产业一线观察、对官方信息的专业解读等，能够提供宝贵的线索和不同于机构研报的视角。机构研报虽然等级更高，但中国机构很多报喜不报忧，可信度也未必绝对可靠。

**有风险的一面：** 同时充斥着大量情绪化言论、庄托、谣言和利益相关方的刻意引导；近两年还叠加了大量 AI 生成的"看起来很像研报"的总结帖，这类内容没有一手信息，只是把公开资料重新排列组合。

**权重定位（2026-10-27 起）：** 在本项目的个股与产业链研究中，**雪球等社区中"身份可追溯、细节可核查"的一手观察帖，权重高于机构研报的二手推论**。前者视为"准 C 级证据"，可以直接参与结论；后者只用于记录市场预期。但社区帖子**永远不能单独支撑重大数字**，且必须通过下面的倾向性检查。

因此采用独立的处理规则：

**第一步：尝试交叉验证。**
发现有价值的线索后，先用其他独立来源验证——通过联网搜索寻找是否有 A/B/C 级来源支持或否定同一说法。

**第二步：如果找到独立验证，正常采信。**
通过至少两个独立的高等级来源（A/B 级）或三个相互独立的 C 级来源验证后，信息可以进入事实和结论，并注明原始线索来源和验证链路。

**第三步：如果找不到独立验证，按以下规则分级处理。**

很多情况下雪球上的信息确实是独家的、提前的、无法从任何正式渠道找到验证的——比如业内人士在财报前透露产能数据、工厂员工发帖说产线状态、供应链人员爆料订单变化等。这些信息后续常常被事实证明是正确的，但因为找不到独立验证就完全丢弃，会错过重要的领先信号。

因此，当雪球/股吧上的信息无法找到 A/B/C 级独立来源验证时，**不机械按未知处理**，而是根据信息本身的质量分两档：

**可用的未验证信号（可以作为决策参考，但不能作为唯一依据）：**

- 信息具体、有时间/地点/数字等可核查的细节（不是"业绩不错""行业很好"这种模糊说法）
- 发帖人有可追溯的历史发言记录，且历史记录显示其对该行业/公司有一定了解
- 信息涉及的是客观事实层面（产能、订单、价格），而不是主观判断层面（目标价、估值高低）
- 信息逻辑自洽，不与已知的 A/B 级事实冲突

符合以上特征的未验证信息，可以：
- 作为辅助信号进入分析，但必须明确标注"未经验证，仅为雪球/股吧线索"
- 用来调整对一只股票的信心程度——比如原本只想建 2% 试探仓，如果有一个高质量的未验证正面信号，可以建 3%；或者原本想重仓，提示有一个未验证负面信号，可以等验证后再加
- 用来质疑机构一致预期、识别潜在风险、或形成"需要重点跟踪什么"的观察清单
- **不能**作为交易决策的唯一理由或主要依据——不能因为一条未验证的雪球帖子就直接重仓买入或恐慌卖出

**不可用的信号（丢弃）：**

- 信息模糊，缺乏可核查的具体细节
- 纯情绪化、口号式、或明显利益导向的言论
- 发帖人历史记录不可追溯或明显是水军/营销号
- 与已知的 A/B 级事实明显矛盾
- 涉及主观价值判断（"严重低估""必然翻倍"）而非客观事实

对于不可用的信号，按噪声处理，不进入任何分析。

#### 3.2.1 AI 生成内容的识别与降权

社区里的 AI 生成帖**低于 D 级，一律不作为证据**。它们最多提供"该去查什么"的关键词线索，不得进入事实、预测、估值假设或交易结论，也不得计入"相互独立的来源"（同一提示词可以批量产出几十篇措辞近似的帖子）。

满足以下特征中的 **3 条及以上**，即按 AI 生成内容处理：

1. **只有框架没有细节**：通篇"三大逻辑""五个维度""四重驱动"，但没有任何可核查的日期、金额、料号、产能数字或具体客户；
2. **与公告/研报高度同构**：逐段改写痕迹明显（同义词替换、语序调换、把两篇研报拼接），观点与其引用材料完全一致；
3. **没有任何个人痕迹**：无持仓、无交易记录、无从业或调研经历、无"我在某厂/某供应商"一类可追溯线索；
4. **结论两头都占**："短期承压、长期向好""估值合理但需警惕风险"，没有可被证伪的明确判断；
5. **排版模板化**：固定小标题 + emoji + 表格 + "风险提示"结尾，段落长度异常均匀；
6. **数字无法追溯**：给出一堆精确到小数点的数字，但任何一个都找不到 A/B/C 级出处，或量级与财报明显不符；
7. **账号行为异常**：一天覆盖多个不相关行业、发布频率机械、从无回复互动；
8. **评论区无实质讨论**：作者从不回应质疑，或只在引流。

**例外：** AI 辅助创作但帖子内**附带了可核验的一手材料**（公告原文截图、实测数据、产线照片、报价单）时，按所附材料本身的质量评估，忽略其结论性文字。

#### 3.2.2 社区信息的倾向性与反操纵检查（每条重要社区证据必做）

雪球是用户大本营，发言天然带立场且经常不准确。采用任何一条社区信息前，逐项检查：

- **利益关系**：是否披露持仓、是否喊单荐股、是否引流私域/卖课/卖软件；未披露利益关系又含明确买卖暗示的，直接降为噪声；
- **时间戳**：发帖时间是否**早于**公告或行情变化（真领先），还是事后复盘（伪领先）；事后帖不得当作"提前预判"的证据；
- **可编辑性**：是否事后修改或删帖；截图与原帖不一致时以原帖为准，无法核验则降一档；
- **选择性举证**：是否只给单季不给累计、只给扣非不给归母、只给有利分部；发现选择性呈现即降一档；
- **拉踩与话术**：是否与一批账号使用相同措辞攻击同业或吹捧同一标的（水军特征）；
- **幸存者偏差**：只引用自己预测成功的旧帖、回避失败记录时，其历史可信度不予采信。

检查通过的信息才进入上面的"可用未验证信号"档；任一项不通过，降一档或直接丢弃，并在内部证据索引中记录降级原因。

#### 3.2.3 召回要求（"提高权重"必须落到检索动作，而不只是允许采信）

每条个股与每条产业链研究，**至少执行 1–2 条专门面向社区的检索**，不得只依赖公告、研报和财经媒体：

- 个股：`<公司名> 雪球`、`<公司名> 产能/订单/良率/价格 讨论`、`<公司名> 调研 一线`、`<公司名> 从业`；
- 产业链：`<环节> 交期/涨价/砍单 雪球`、`<上游材料> 供给 讨论`；
- 命中的高质量帖必须登记进内部证据索引（作者身份线索、发帖时间、可核查细节、是否通过 3.2.2 检查），并在结论中体现其影响方向；
- 如果检索后确认"没有可用的社区一手信息"，也要在研究文件里写明"已按 3.2.3 检索、无可用社区证据"，不得默默跳过。

机构研报与社区信息的**分工**：研报回答"市场现在怎么想"（预期、评级、目标价、一致预期的位置），社区一手观察回答"一线正在发生什么"（产能、订单、交期、良率、渠道库存、员工/供应商侧的变化）。两者冲突时，先查一手数据；查不到时并列呈现并标注分歧，不得默认研报正确。

### 3.3 百家号

百家号是百度自媒体平台，内容质量普遍极低，常见入口包括 `baijiahao.baidu.com`、`mbd.baidu.com` 及标注"百家号"的百度作者页面。

- 百家号**只能提供搜索关键词灵感**，不能进入任何事实、预测、估值假设或交易结论。
- 不得因为标题中出现公司名、证券代码或精确数字而提高其证据等级。
- 如果搜索结果只有百家号内容，视为"无可靠来源"，按未知处理。

### 3.4 通用证据准入规则

**核心原则：任何重要结论都不能只依赖单一来源，必须经过交叉验证。**

- 重大事实和关键结论应有至少一个 A/B 级来源。
- A/B 级来源确实不存在时，可以使用两个相互独立的 C 级来源，并明确说明证据降级和不确定性。
- 卖方研报只作为"市场预期与机构立场"的记录：其中的数字必须回溯到 A/B 级一手资料，回溯不到时标注"仅研报口径"，不得用它替代公告或交易所文件。
- **AI 生成内容、内容农场改写稿、同一来源在多平台的搬运版本，都不计入"相互独立的来源"**；用它们凑够"两个独立来源"属于伪造交叉验证。
- 即便使用了 A/B 级来源，也应在条件允许时搜索是否有其他独立来源支持或反驳同一结论——单一来源永远不如多源交叉验证可靠。尤其注意机构研报可能存在报喜不报忧的倾向，能用公司公告、交易所文件或第三方独立数据交叉验证的，就不要只依赖研报。
- 多个网站转载同一篇文章、同一匿名爆料或同一搜索摘要，不算相互独立的来源。
- 搜索结果中只有雪球/股吧的未验证信息时，按 3.2 节的分级规则处理——高质量未验证信号可以保留并标注，低质量的丢弃。搜索结果只有百家号或其他纯 D 级来源时，按未知处理。
- 不得用低质量内容填补证据空白。
- 来源等级只解决可信度，不代替时效检查；即使是 A/B 级来源，也要核对发布日期和适用期间。

## 四、证据最小信息与最终输出边界

过程研究文件、抓取缓存或内部证据索引中的每条重大证据记录：

- 事实或原始数字；
- `period_end`；
- `release_date`，可得时记录时间；
- `fetched_at`；
- 来源标题与 URL；
- 来源类型；
- 口径、单位和可信度；
- 它支持或反驳哪个结论。

上述来源元数据只用于内部核验。所有最终交付文件禁止输出 URL、Markdown 链接、脚注、括号来源标注或独立来源清单。A/B/C 级资料直接吸收为事实与结论，不展示引用。只有雪球、股吧、社交媒体传闻等低可信信息确实影响判断时，才在最终正文标注“低可信来源”或“未经证实”并说明影响；仍不得展示来源名称、标题或 URL。

历史复盘按 `release_date` 判断当时可见性，不按 `period_end`。

若角色输出契约没有独立证据字段，过程文件可记录必要的日期、来源名称、来源等级和结论影响，不得擅自增加 JSON 字段；最终文件只保留事实日期与结论影响，常规来源信息全部移除。

## 五、搜索循环

围绕当前知识缺口构造搜索，而不是机械执行固定问题列表：

```text
提出缺口
→ 按运行环境选择的搜索入口召回
→ 按 3.1~3.3 分级处理来源（雪球/股吧按 3.2 分级评估，百家号按 3.3 仅保留关键词）
→ 追溯并选择高等级来源
→ 打开原文核对
→ 搜索是否有独立来源支持或反驳同一结论
→ 更新结论
→ 检查是否出现新冲突或缺口
```

当重大问题仍缺证据时继续搜索；当公开信息确实没有答案时，明确写未知及影响，不得用低质量内容填空。
