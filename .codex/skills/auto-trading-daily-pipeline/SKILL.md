# 4. 标准工作流（半自动确认版）

## 日期选择说明
- **用户在触发 Skill 时会提供日期**（格式：`YYYY-MM-DD`）
- Agent 根据此日期定位到 `data/skill_runs/YYYY-MM-DD/` 目录
- 所有文件读取和决策输出都基于该日期目录

## 阶段 A（自动，由 Agent 完成）

### 步骤 1：确认日期和定位目录
根据用户提供的日期（YYYY-MM-DD），定位到 `data/skill_runs/YYYY-MM-DD/` 目录。

### 步骤 2：读取分析指引和规则
读取 `03_agent_input.md`：
- 先理解规则与输出格式
- 按照 `03_agent_input.md` 要求输出你对规则的理解和持仓信息
- **⚠️ 特别注意**：`03_agent_input.md` 中包含的【最终总结生成规则】(final_summary_rules) 定义了 `05_decision.json` 的输出格式，必须牢记此格式！

### 步骤 3：读取基本面数据概览
阅读 `02_basic_snapshot_payload.json`（昨日《基本面数据概览》用于对昨天股池中各股情况进行快速扫描）。

### 步骤 4：读取宏观和大盘信息
阅读 `01_global_context.md`（宏观/上证/渐进式新闻总结）。

### 步骤 5：读取上一交易日的决策（保持连贯性）
**⚠️ 关键步骤：在分析个股之前，先阅读上一交易日的决策文件**
- 定位上一个交易日：在 `data/skill_runs/` 目录下找到日期早于当前日期的最近一个目录
- 读取该目录下的 `05_decision.json` 文件
- **目的**：了解上一次对每只股票的估值逻辑、目标价、止损价，保持决策和估值的连贯性
- 对于持仓股票，必须在今日分析中回溯上一次的估值假设，评估是否需要调整

### 步骤 6：逐只深度分析股票
按需阅读 `04_stock_research/` 中的更详细个股研究资料：
- **⚠️ 必须逐只串行分析**（详见第8节规则）
- 每只股票：读取研究包 → 五维分析 → SOTP估值 → 输出结论 → 立即完成该股庭审（动议初筛 + 正反辩论 + 法官裁决）→ 再读下一只
- **估值输出不能只写结论**：每只股票在分析阶段就要形成“明日可继续复用的估值记忆锚”，至少写清楚现价、估值方法、关键假设、悲观/中性/乐观三档、概率权重、概率加权目标价、预期收益率、风险收益比，以及这些数字如何推导出来
- 禁止一次性读取所有股票的研究包

### 步骤 7：汇总逐股分析与逐股庭审结果
- 按照 `03_agent_input.md` 中的规则，汇总每只股票在步骤 6 中已完成的【交易动议初筛】、【庭审辩论】和【法官裁决】
- 确保每只股票在进入下一只之前，当前股票的庭审结论已经完整输出
- **⚠️ 到此必须停住，等待人工确认**

### 步骤 8：人工确认后生成决策文件
**⚠️ 只有在用户明确回复"OK 生成决策"或类似确认后，才执行此步骤**
- 将所有分析和庭审结果整理成 JSON 格式
- **严格遵守** `03_agent_input.md` 中的【最终总结生成规则】格式
- 生成 `data/skill_runs/YYYY-MM-DD/05_decision.json` 文件
- `05_decision.json` 中每只股票的 `reason` 必须是“详细估值底稿 + 庭审记录”，而不是一句话摘要；默认目标是让下一交易日的 Agent 只看 `reason` 也能迅速恢复昨日估值锚和判断边界
- **分段生成策略**：不要一次性生成全部内容，先生成框架和前几只股票，再分批追加，防止出错
- 生成完成后，**再次停住，等待人工检查决策文件**

## 阶段 B（人工确认，两次确认点）

### 第一次确认：生成决策前
- **时机**：Agent 完成所有股票的逐股分析与逐股庭审汇总后（步骤 7 完成）
- **内容**：用户检查分析结论和庭审裁决
- **操作**：用户回复"OK 生成决策"或"继续生成 JSON"
- **作用**：确认分析逻辑无误后，Agent 才开始生成 `05_decision.json`

### 第二次确认：执行交易前
- **时机**：Agent 生成 `05_decision.json` 完成后（步骤 8 完成）
- **内容**：用户检查 `05_decision.json` 文件内容
- **操作**：用户明确回复"OK 执行"
- **作用**：确认决策文件格式和内容正确后，才进入阶段 C 执行交易

## 阶段 C（自动执行）
1. 调用 `execute_trade_from_decision.py`（这个脚本通过 MCP 执行 buy/sell）。
2. 调用 `merge_trade_summary.py`（这个脚本会写入每日总结并合并历史）。
或直接调用`scripts/run_post_trade.py`(包含相同的执行交易和合并总结的功能)。

# 8. 逐股分析规则（强制，至关重要）

**⚠️ 重要警告**：一次性读入过多 token 会严重影响 AI 分析效果，必须遵守以下规则：

## 8.1 禁止批量读取
- **❌ 禁止**：一次性读取所有股票的 `_research.md` 文件
- **❌ 禁止**：在分析开始前将全部研究包内容加载到上下文中

## 8.2 正确的分析流程（逐股串行）
假设需要分析 5 只感兴趣股票，必须按以下顺序执行：

```
股票1: 读取研究包 → 五维分析 → SOTP估值 → 输出结论 → 动议初筛 → 庭审辩论 → 法官裁决 → 释放上下文
    ↓
股票2: 读取研究包 → 五维分析 → SOTP估值 → 输出结论 → 动议初筛 → 庭审辩论 → 法官裁决 → 释放上下文
    ↓
股票3: 读取研究包 → 五维分析 → SOTP估值 → 输出结论 → 动议初筛 → 庭审辩论 → 法官裁决 → 释放上下文
    ↓
...
```

## 8.3 执行要求
1. **逐只读取**：每次只读取当前正在分析的那只股票的 `_research.md`
2. **完整分析**：对该股票完成五维透视 + SOTP分部估值 + 风险收益比计算
3. **输出结论**：输出该股票的【全维综合总结】
4. **立即庭审**：当前股票分析完成后，立刻完成该股的【交易动议初筛】、【正反方辩论】和【法官裁决】
5. **再读下一只**：确认当前股票的庭审裁决已经完成后，再读取下一只股票的研究包

## 8.4 违规后果
违反此规则会导致：
- 分析质量下降（AI 在超长上下文中容易遗漏关键信息）
- 估值计算错误
- 决策逻辑混乱

**Agent 务必严格遵守此规则！**

# 9. 估值记忆锚写作规范（强制）

`05_decision.json` 里的 `reason` 不只是“今天为什么买卖/持有”的解释，同时也是**下一交易日继续分析的记忆锚**。因此，估值部分必须写成可复盘、可接续、可修正的推导链，而不是一句“估值不贵/略低估/目标价 XXX”。

## 9.1 写作目的
- 让下一次分析时，Agent 不必重新猜测你昨天到底用了什么盈利预期、什么倍数、为什么给这个目标价。
- 让用户能直接复盘：如果未来业绩、行业景气度或估值中枢变化，到底应该修改哪一段假设。
- 让 `07_daily_summary.json` 与 `08_history_merge.json` 在后处理时继承的是“有细节的估值底稿”，而不是空泛结论。

## 9.2 必写结构
对每只股票，`reason` 中至少要按以下顺序写出估值链；`BUY` / `SELL` / `HOLD` / `FLAT` 都适用，不能因为“不交易”就省略估值：

1. **【当前价格与历史锚点】**
   - 写清楚分析日期、当日现价、是否触及上次目标价/止损价。
   - 对持仓股，必须回溯上一交易日或最近一次深度分析的估值锚：昨天/上次用的利润假设、目标价区间、关键关注点今天有没有变化。

2. **【估值方法选择】**
   - 说明为什么采用 PE / PB / PS / SOTP / 单业务整体估值。
   - 如果公司业务单一，也要明确说明“不拆分”的原因；如果是周期股，优先说明为什么改用 PB / PS，而不是只写“周期股看 PB”。

3. **【关键经营假设】**
   - 把用于估值的核心基数写出来：例如 2026E 净利润、分部利润、净资产、收入、ROE、股本。
   - 如果分部利润不是研报直接给的，要说明是如何估出来的（例如按营收占比、利润率、管理层指引、机构一致预期拆分）。

4. **【三情景估值推导】**
   - 悲观 / 中性 / 乐观三档必须分别写出：
     - 对应盈利或净资产假设
     - 对应估值倍数区间及其依据
     - 推导出的总市值
     - 折算后的目标股价
   - 若为 SOTP，必须尽量写出“分部利润 × 分部倍数 = 分部估值，再加总”的过程。
   - 若为周期股，可写成“每股净资产 × 目标 PB = 目标价”或“收入 × PS = 目标市值”，但必须把公式和数字写出来。

5. **【概率权重与期望值】**
   - 写清楚悲观 / 中性 / 乐观三档概率权重。
   - 写出概率加权目标价 `expected_target` 的计算过程，而不是只报最终结果。
   - 写出预期收益率 `expected_return_pct` 和风险收益比 `risk_reward_ratio` 的计算口径。

6. **【结论与动作映射】**
   - 说明为什么最终动作是 BUY / SELL / HOLD / FLAT。
   - 如果 `price_target` 没有直接采用 `expected_target`，必须解释差异：例如执行层更保守、分批止盈、技术阻力位限制等。
   - 如果因为预期收益率不足 15% 或风险收益比不足而放弃买入，也要把数字写完整，而不是只写“赔率不够”。

7. **【次日继续跟踪的变量】**
   - 写清楚未来哪几个变量一旦变化，会导致估值上调或下调，例如：销量、ASP、原材料、在手订单、财报兑现、监管政策、产品价格。

## 9.3 写作禁令
- **禁止**只给一个目标价，不写假设来源。
- **禁止**只写“悲观/中性/乐观约为 XXX”，不写盈利基数、倍数与推导过程。
- **禁止**只写“估值不贵”“中性偏低估”“继续观察”这类没有数字锚点的空话。
- **禁止**因为最终动作是 `HOLD` 或 `FLAT` 就省略详细估值；不交易同样需要说明“为什么现在不值得动”。
- **禁止**在 JSON 顶层新增额外估值字段；所有估值细节仍然只写在 `reason` 中。

# 10. 庭审流程强制规则（逐股执行，决策输出前提）

**⚠️ 在输出最终决策 JSON 之前，必须完成完整的庭审流程！**

## 10.1 禁止跳过庭审
- **❌ 禁止**：分析完股票后直接输出 `05_decision.json`
- **❌ 禁止**：省略【庭审步骤 1】动议初筛 和【庭审步骤 2】庭审辩论
- **❌ 禁止**：在没有正反方辩论的情况下做出买卖决策
- **❌ 禁止**：先把所有股票都分析完，再回头集中进行庭审

## 10.2 正确的决策流程

```
逐股循环:
    1. 读取当前股票研究包
    2. 完成五维透视 + SOTP估值
    3. 输出该股票分析结论
    4. 庭审步骤 1: 【交易动议初筛】
       - 判断该股票是否触发动议（买入/卖出/持有）
       - 记录动议类型和证据链
    5. 庭审步骤 2: 【庭审辩论】
       - 围绕该股票进行正反方辩论
       - 正方陈述 → 反方质询 → 法官裁决
       - 输出该股票庭审结论
    6. 完成当前股票后，才进入下一只股票

全部股票完成后:
    - 汇总各股票的分析结论与庭审裁决
    - 根据逐股庭审结果生成 `05_decision.json`
```

## 10.3 庭审必须输出的内容
在 `reason` 字段中必须包含：
1. 【动议类型】：💰买入 / 🛡️卖出 / ⚖️调仓 / 维持持有
2. 【正方论据】：为什么应该执行该操作
3. 【反方质疑】：风险点和反对理由
4. 【法官裁定】：最终决定及理由

## 10.4 输出路径与生成策略
最终决策必须输出到：`data/skill_runs/YYYY-MM-DD/05_decision.json`
