# 输出契约

## 1. 输出目标

输出不是"新闻列表"，而是"主题级研究记忆"。

一个明天才上线的全新 agent，只读今天的 `06_hot_news_state.json`，也应该能够理解：

1. 这个主题为什么进入主上下文
2. 它过去几天怎么发展到今天
3. 今天发生了什么新增变化
4. 当前市场到底在交易这个主题的什么部分
5. 接下来可能怎么发展
6. 有哪些证伪或反转风险
7. 明天还要继续跟踪什么
8. 它关联哪些宏观主题、板块和股票

## 2. 顶层结构

```json
{
  "run_date": "2026-04-03",
  "market_regime_bridge": "一句话说明今天宏观变化如何映射到可交易叙事",
  "active_themes": [],
  "cooling_themes": [],
  "new_themes": [],
  "universe_expansion_hints": [],
  "summary": {}
}
```

## 3. 输出的JSON结构介绍

每个主题只保留 **12 个字段**（旧版 18 个），删除了冗余字段：

- 删除：`key_events`（与 `today_update` 重叠）、`forward_paths`（与 `scenarios` 重叠）、`expected_duration`（合并到 `current_state`）、`evidence_news_ids`（实现细节）、`search_trigger`（合并到 `next_day_watchlist`）

## 4. 主题字段说明

### 4.1 `history_anchor`

渐进式总结的核心字段。每天从旧文件的同名主题继承并追加到今天，形成完整的演变链。

应包含：

1. 主题最初进入主上下文的原因
2. 过去几天最关键的变化链（因果链、拐点事件）
3. 当前判断的历史依据
4. 关键时间节点和方向性切换的上下文

**格式建议**：按时间线分段叙述，用 `\n\n` 分隔每日/每个阶段的更新。信息密度要高，不追求文笔优美。

### 4.2 `today_update`

只描述今天相对昨天新增了什么。用简洁条款而非长篇散文。

应包含：

1. 关键新闻（每条 1-2 句话）
2. 新表态、新事件
3. 资金或板块层面的新确认

**格式建议**：用 `；` 或 `\n` 分隔不同事件。按重要性排列，最重要的在最前。不加 emoji。

### 4.3 `current_state`

把"历史锚点 + 今日变化"压缩成当前状态结论。应同时说明：

1. 市场今天到底在交易这个主题的什么部分
2. 这条线是强化、分化、衰减还是等待确认
3. 主题已持续多久、处于什么阶段（刚启动 / 中段强化 / 高位拥挤 / 退潮前夜）
4. 可能的衰减信号是什么

长度建议：150-300 字。宁可简洁，不要面面俱到。

### 4.4 `scenarios`

把主题未来的主要情景分支结构化。合并了旧版 `scenario_tree` 和 `forward_paths` 的功能。

每个情景包含：

1. `scenario` — 情景描述（1-2 句话）
2. `probability_band` — 概率区间，用 `high / medium / low / low_to_medium / medium_to_high`
3. `trigger_signals` — 触发该情景的关键信号（3-5 条）
4. `market_impact` — 对 A 股市场、板块、风格的近端影响（1-3 句话，具体到板块和风格轮动）

注意：

1. 不是宏观长周期预测，只写和选股、板块、市场风格相关的近端路径（1-5 个交易日）
2. 不能只写单向乐观路径，必须同时覆盖延续、钝化、反转等主要分支
3. 建议 3-4 个情景覆盖主分支
4. `market_impact` 要具体（"航空/消费/化工受益，油气/军工/黄金承压"），不要泛泛（"利好股市"）

### 4.5 `key_risks`

显式提醒后续 agent：这个主题可能如何被证伪、降温或反转。每条风险应包含：

1. `risk` — 风险描述
2. `probability_band` — 同 scenarios 的概率区间
3. `why_it_matters` — 为什么这个风险重要，对交易意味着什么

建议保留：

1. 会直接改变主题方向的风险
2. 会导致板块先于新闻反转的交易风险
3. 会导致股票选择发生明显切换的结构风险
4. "市场已过度交易"类的拥挤风险

### 4.6 `next_day_watchlist`

为明天的新 agent 提供明确跟踪清单。要求：

1. 尽量具体（不是"跟踪板块"而是"跟踪 XX 板块是否突破 MA20"）
2. 可执行（明天 agent 能直接搜索或核验）
3. 可被搜索或核验
4. 包含板块强化时的扩展搜索触发（如"若板块继续强化，应搜索宇宙外龙头"），替代旧版 `search_trigger` 的功能

## 5. 哪些新闻应该进入这个系统

应进入主主题系统的内容：

1. 会改变市场叙事的宏观、政策、产业、地缘新闻
2. 会驱动板块或赛道重估的行业级事件
3. 少量对板块或市场有外溢性的公司事件

不应进入主主题系统的内容：

1. 普通财报
2. 小额担保
3. 常规减持、增持
4. 对板块和市场没有扩散意义的日常公告

对于这类单公司信息，更适合进入：

1. 个股 snapshot
2. 股票侧观察清单
3. 股票侧决策日志

## 6. 主题如何映射到股票

主题层不直接负责最终选股，但必须提供股票映射线索。

建议至少输出：

1. `linked_symbols_in_universe` — 宇宙内相关股票
2. `outside_universe_names_to_check` — 宇宙外值得关注的标的

作用：

1. 帮助 agent 在宇宙内优先看哪些股票
2. 触发 agent 在宇宙外搜索新的龙头或弹性股
