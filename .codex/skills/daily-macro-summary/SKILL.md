# Daily Macro Summary

## 何时使用

- 用户要更新当天宏观总结
- 用户要生成 `data/macro_economy/YYYYMMDD.md`
- 用户要做“渐进式宏观新闻总结”而不是一次性长篇宏观研报

## 日期语义（必读）

- 本 skill 所有路径、文件名、正文日期与 `AGENTS.md` 的 `--date` 口径完全一致，指**要分析的交易日**
- **日期选择规则**：
  - 用户显式指定了日期 → 使用用户指定的日期
  - 用户未指定日期 → 直接用最新的`today`
- 输出文件名的 `YYYYMMDD` 与宏观客观数据面板日快照的 `YYYY-MM-DD` 都使用这个日期

## 输出路径

- 输出到：`data/macro_economy/YYYYMMDD.md`（`YYYYMMDD` = 要分析的交易日）
- 宏观客观数据面板缓存位于：`data/global_cache/macro_objective_panel/`
  - 日快照：`data/global_cache/macro_objective_panel/daily_snapshots/YYYY-MM-DD.json`（同样 = 要分析的交易日）
  - 最新快照：`data/global_cache/macro_objective_panel/latest.json`

## 文件操作规则（重要）

**根据当日文件是否存在，采用不同策略：**

### 情形 A：当日文件已存在（最常见）

1. 用 `cp data/macro_economy/YYYYMMDD.md data/macro_economy/YYYYMMDD.md.bak` 备份原文
2. 完整读取原文，理解现有内容和数据来源
3. 读取面板快照，比对哪些数字需要更新
4. 搜索当日新增事件
5. **只用 `Edit` 工具对需要修改的段落做定点替换**，不要全量 Write 重写
   - 修改面板表格中的数字行
   - 补充新增事件到对应章节
   - 更新数据口径说明头部
6. 备份文件 `*.md.bak` 确认无误后可删除，或保留供比对

### 情形 B：当日文件不存在，但前一日文件存在

1. 用 `cp data/macro_economy/YYYYMMDD_prev.md data/macro_economy/YYYYMMDD.md` 以前日文件为模板
2. 完整读取，再按情形 A 流程用 Edit 做增量更新
3. 重点：修改文件标题日期、数据口径说明、面板数字、今日变化摘要

### 情形 C：基线重建（`data/macro_economy/` 为空 或 最近文件超过 7 天）

- 直接用 `Write` 全量生成新的高信噪比基线文件
- 参考"三种运行模式 → 基线重建模式"的流程

## 先读什么

1. **先检查 shared_data_access 的宏观客观数据面板**
   - 优先读取 `data/global_cache/macro_objective_panel/daily_snapshots/YYYY-MM-DD.json`
   - 若当日快照不存在，读取 `data/global_cache/macro_objective_panel/latest.json`
   - 若两者都不存在，再考虑自行抓取硬数据；不要默认先联网搜 US10Y、黄金、油价、LPR 这些客观面板
2. 找到 `data/macro_economy/` 下日期早于等于今日的最近一份文件
3. 先完整阅读最近一份宏观总结，恢复“昨天的状态机”
4. 若最近一份文件距离今天超过 7 天，再额外把最近一次“高质量基线文件”作为参考

读者假设：

- **今天产出的文件默认是给“明天重新开始的新 AI”读的**
- 可以假设明天的新 AI 能读到今天这份文件，但**不能假设它会回头读昨天或更早的文件**
- 因此今天文件必须独立保留当前仍有效的背景、关键节点、最新进展和资产映射，不能把关键信息藏在前一天文件里

强制规则：

- **最近一份宏观总结必须从头到尾完整读完**
- 若文件较长，必须分段顺序读到结尾
- **禁止**只靠 `rg`/关键词搜索/局部摘录来理解昨天的宏观框架
- 只有完整读完最近一份文件后，才允许开始做今天的增量更新判断

## 三种运行模式

### 1. 基线重建模式

满足任一条件时，优先进行深度搜索：

- `data/macro_economy/` 为空
- 最近一份文件距离今天超过 7 天
- 宏观 regime 明显切换，且旧基线已经失真
  - 例：美联储/中国央行/日本央行重大转向
  - 例：中东、俄乌、关税战出现质变
  - 例：中国重大会议明显改口径

目标：

- 生成一份新的“高信噪比基线”
- 不求面面俱到，但必须把后续日更最需要继承的结构和锚点写清楚

### 2. 强化更新模式

满足任一条件时：

- 最近 24 小时有重磅数据发布
  - 中国 CPI/PPI/社融/PMI/出口
  - 美国 CPI/PCE/非农/零售销售/FOMC
- 主要央行刚开完会或核心官员密集讲话
- 金价、油价、美债收益率、美元指数出现异常波动
- 持续性风险事件出现方向性变化

目标：

- 做“事件级增量更新”
- 只更新真正改变市场定价的部分

### 3. 日常增量模式

默认模式。优先使用本地 agent 自带的免费普通搜索工具。

目标：

- 刷新硬数据
- 核验当天是否有实质新增
- 若没有新增，沿用昨天的核心判断，只更新日期和价格/数据面板

## 工具使用顺序

1. **先读 shared_data_access 的宏观客观数据面板**
   - 这是硬数据主源，优先消费已经结构化缓存好的客观指标
   - 适用对象：`US10Y / US02Y / 中国10Y国债 / USD-CNH / COMEX黄金 / 伦敦金 / Brent / WTI / LPR`
   - 当前已知限制：`DXY` 可能降级为 `warning`，`Fed / BOJ / ECB` 在当前数据源下可能只有 `stale` 历史值；看到这些状态时，必须再做额外核验
2. 再读本地 `data/macro_economy` 最近文件
3. 搜索阶段默认先用本地 agent 自带的免费普通搜索工具
4. 需要多轮交叉验证时再用 `deep_search`
5. 只有基线重建或高复杂度 regime 切换时才用 `deep_research`

补充规则：

- Routine 日更不要默认上 `deep_research`
- **不要绕过 shared_data_access 重新抓取那些已经在宏观客观数据面板里的硬数据，除非面板缺失、状态为 `warning/stale`、或你需要更高频/更高精度口径**

## 美股实时信息搜索规则（强制）

**每天必须搜索当天最新的美股信息**，根据当前北京时间判断应搜索什么：

| 北京时间 | 美股状态 | 应搜索内容 | 搜索示例 |
| :--- | :--- | :--- | :--- |
| 06:00–20:00 | 收盘/休市 | 前一交易日收盘数据 + 当天盘前期货 | `美股 收盘 道指 纳指 YYYY年MM月DD日` |
| 20:00–21:30 | 盘前交易 | 盘前期指走势 + 前日收盘回顾 | `美股 盘前 期货 道指 纳指 YYYY年MM月DD日` |
| 21:30–次日04:00 | 盘中交易 | 实时盘中行情 + 板块表现 | `美股 盘中 道指 纳指 实时 YYYY年MM月DD日` |
| 04:00–06:00 | 盘后交易 | 收盘数据 + 盘后重要个股 | `美股 收盘 盘后 YYYY年MM月DD日` |

执行要求：

- **不管当天其他新闻多少，美股搜索不得跳过**
- 搜索关键词必须同时包含中英文，例如同时搜 `美股 6月11日 盘前` 和 `US stock futures premarket June 11`
- 搜索结果必须填入宏观总结的市场面板、美股相关小节和资产映射中
- 若搜索无当天结果（数据延迟），至少标注"截至当前暂无当日美股数据"，并在未来关注中备注应补充
- 盘前/盘中搜索时，需重点关注：三大期指涨跌幅、芯片/科技板块盘前表现、重要个股异动（如甲骨文盘后、超微电脑等）

## 每日必须刷新的硬数据

至少刷新以下面板中的有效项目；若当日无新值，明确写“沿用上次发布值”：

- 美联储：最新利率区间、下一次会议时间、降息/不降息主流预期
- 中国央行：LPR、MLF、逆回购、流动性投放方向、汇率稳汇率表态
- 日本央行、欧洲央行：最新利率与下一步政策预期
- 美国：10Y/2Y 美债、DXY、非农、CPI/PCE、零售销售
- 中国：CPI/PPI、社融、M1/M2、PMI、出口
- 市场价格：COMEX/伦敦金、Brent/WTI、USD/CNH

执行要求：

- **优先把 shared_data_access 宏观客观数据面板作为“硬数据底板”直接引用到正文**
- 若面板里某项状态为 `ok`，默认视为当日客观数据主源，不再重复搜索同一指标
- 若面板里某项状态为 `warning` 或 `stale`：
  - `warning`：说明抓取失败或不可用，必须额外核验
  - `stale`：说明只有历史有效值，可写入“沿用最近有效值”，但必须补充最新政策/会议状态核验
- 对 `Fed / BOJ / ECB` 这类政策变量，不要因为面板里有历史利率值就省略会议和预期更新；它们仍然需要搜索最新政策口径
- 对 `DXY`，若面板为空或 `warning`，应把它视为待补位项，而不是直接跳过

## 持续性事件的“节点压缩”规则

对战争、关税、地产风险等持续性事件，不要每天重写完整编年史；但也**不能**只剩“升级/缓和/僵持”这种结果词。正确做法是：

- **远端背景压缩**：更早的历史只保留 1-2 句最小背景，解释“谁和谁、冲突点/风险点是什么、为什么会进入资产定价”
- **中段节点提炼**：若事件已持续多天，只挑仍然决定当前市场框架的 2-4 个关键节点
- **近期进展展开**：重点写最近 1-3 天的新增进展，以及这些进展如何传导到油价、黄金、利率、央行预期、A/H 股和美股

对每个仍保留在正文里的持续性事件，至少保留以下 5 个部分：

1. **最小背景**：冲突/摩擦双方是谁，当前在争什么，为什么它会进入全球资产定价
2. **关键节点链**：从事件启动以来，只保留 2-4 个仍然影响当下判断的重要节点，尽量给日期
3. **最近几天最新进展**：优先覆盖最近 1-3 天的实质新增；若无新增，明确写“最近几天无实质新增”
4. **当前状态判断**：升级 / 缓和 / 僵持 / 已被市场基本消化，但必须解释“具体在什么维度上升级或缓和”
5. **资产与政策传导链**：把事件如何影响油价、航运、避险、通胀、利率、Fed/PBOC 预期以及相关股票板块串成完整链条

写作要求：

- 若战争已持续 15 天，不要把 15 天逐日罗列；只保留最关键的几个节点，再重点展开最近几天的进展
- 每天都要重新搜索这些持续性事件的最新进展，而不是机械沿用旧表述
- 只要事件仍是市场主变量，就必须把“最新进展 + 资产价格变化 + 宏观预期变化”放在同一段逻辑里写清楚

可以删除的是：

- 超过 7 天且已经不再影响当前定价的细碎战报、零散评论或重复表态
- 对理解今天市场没有帮助的长篇历史回顾

不能删除的是：

- 让一个完全不知道上下文的读者理解“现在到底发生了什么”的最小背景
- 仍然决定当前价格中枢或政策预期的关键节点
- 最近几天足以改变资产定价的实质新进展

## 输出要求

输出必须是“短而硬”的高信噪比总结，不写成长篇散文。结构优先遵守
[report_contract.md](references/report_contract.md)。

核心要求：

- 先写“今天和昨天相比，变了什么”
- 若无实质新增，沿用昨日内容和事件链发展
- 今日文件必须始终是一份“可独立阅读的宏观总结”：即使没有新增新闻，也必须继续写出当前仍有效的关键价格面板、央行状态、核心宏观数据、仍有效的政策定调和持续性风险状态
- 按“明天会换一个新的 AI，只读今天文件”的标准写作：不能假设读者看过昨天文件；凡是正文第一次提到的央行转向、战争、关税、地产风险，必须在首次出现处详细的描述补足背景，已有的事件，需要搜索并描述详细的事件发展进展，从何时如何发生，到关键变化节点，到最新事件动态，不能只描述事件最新动态
- 持续性事件必须写出“详细事件发展过程、重要节点 -> 然后补足事件发展对最新的资产价格 -> 利率/央行预期 -> 股票/黄金/石油”的链条的影响，最后再阐述未来可能对宏观资产、期货的影响，不能只给结论词
- 数据要尽量写“公布值 vs 预期值”
- 官方案定调与市场/机构解读要分开写
- 区分“已核实事实”与“基于事实的推断”
- 结尾必须给出对 A 股 / 港股 / 黄金 / 石油 / 美股 的一句话映射
- **文末必须新增“未来几天关注事项/Next Watchlist”**：列出明天或未来几天最需要继续跟踪的事件、日期或时间窗口、为什么重要、以及第二天更新时应优先搜索什么

## 不要做什么

- 不要把任何基线 deep research / deep search 长报告原样复制为日更稿；必须压缩、去重并改写成“今日仍然有效的状态快照 + 今日增量变化”
- 不要把每条新闻都记进去
- 不要重复同一个持续事件的冗余历史背景，但要保留能让陌生读者看懂的最低背景
- 不要把持续性事件写成孤立新闻摘要；必须把事件进展与资产价格、利率、预期和相关板块连起来
- 不要只写“利多/利空”而不解释影响链条
- 不要因为没新闻就硬凑内容
- 不要漏掉“未来几天关注事项”；哪怕当天新闻不多，也要把明后几天可能驱动宏观变化的已知事件写出来
