# 行业景气研究系统设计

更新日期：2026-07-14

## 1. 定位

`industry_research` 是独立于每日选股和三账本交易的中长期产业研究层，目标不是找“最近涨得好”的行业，而是回答四个问题：

1. 哪些产业在未来三至五年存在足够大的结构性收入空间？
2. 哪些产业的需求、订单或供给约束正在从预期进入现实？
3. 利润会留在产业链哪个环节，而不是只形成收入增长？
4. 哪些公司既能承接利润，又具备龙头质量和合理市值空间？

系统节奏为：

```text
半年结构空间扫描
→ 月度行业专属领先指标监控
→ 季度全A财务扩散验证
→ 用户确认最多一个主题
→ Agent全产业链深研与利润映射
```

本层不修改 `selection_runs`、`skill_runs`、`01-08`、股票池、仓位或交易规则。

## 2. “爆发式增长行业”的操作定义

“爆发式增长”不是当期营收增速高，也不是行业指数上涨，而是以下三层条件依次成立：

### 2.1 结构空间

- 三至五年基准情景的产业收入空间约为当前的2倍或以上。
- 增长能被终端需求、渗透率、单位价值、国产替代或全球份额公式解释。
- 终局空间不违反经济总量、客户资本开支或下游付费能力约束。
- A股存在能够承接利润的产业链节点。

### 2.2 基本面右侧

- 至少两项新鲜领先指标改善。
- 改善来自至少两个独立类别，例如需求与订单、需求与供给、订单与库存。
- 恶化指标不超过一项。
- 证据来自真实销量、订单、招标、排产、库存、价格、交期、资本开支等产业数据，而不是热点或股价。

### 2.3 财务扩散

- 行业营收和利润增长不只集中在一家公司。
- 正增长公司占比扩大，且连续报告期同比增速出现加速度。
- 财务扩散只验证前述产业判断，不能反过来替代结构空间与领先指标。

## 3. 运行节奏

| 工作 | 频率 | 目的 | 人工负担 |
| --- | --- | --- | --- |
| 申万行业目录刷新 | 每半年或分类变更时 | 保持全行业地图完整 | 无 |
| 全行业结构空间预检 | 每半年 | 从约131个申万二级行业形成10-20个结构候选 | 审阅候选池 |
| 已批准主题领先指标更新 | 每月 | 判断基本面是否进入右侧或转弱 | 审阅少量变化 |
| 全A行业财务扩散验证 | 季报披露窗口后 | 验证增长是否扩散和加速 | 无新增搜索 |
| 单产业链深研 | 每月最多一个 | TAM、供需错配、利润节点、龙头、市值空间 | 用户先确认主题 |
| 状态与证伪条件复核 | 每月/事件触发 | 决定观察、持有研究或退出研究 | 只看变化 |

每日数据频率不等于每日研究频率。本系统明确不把日频热点、板块涨幅、资金流或股票动量作为行业发现输入。

## 4. 四层架构

### 4.1 半年结构扫描层

输入：

- `shared_data_access.industry_catalog` 提供的申万一二三级行业目录。
- `shared_data_access.industry_financial_panel` 提供的最近财务验证快照，可缺失。
- Agent对政府、行业协会、公司、客户和供应商材料的分层深搜。

输出：

- `scan_input.json`：全申万二级行业的统一预检输入。
- `scan_input.md`：供Agent执行轻量分类的任务说明。
- `structural_opportunity_pool.json`：用户审批后的10-20个结构候选主题。

AkShare在这一层负责快速获得完整行业地图和已有统计数据，不负责回答TAM、渗透率或供需错配。Agent先对全部行业低成本预检，再只对最可能的约20个方向深搜，避免为每个申万行业写完整报告。

统一预检问题：

1. 终端需求的计量单位是什么？
2. 当前市场规模和三至五年基准终局空间是多少？
3. 增长来自渗透率、单位价值、国产替代、全球份额还是短期涨价？
4. 下游是否有能力持续付费？
5. A股是否存在真正承接利润的节点？

分类口径：

- `structural_growth`：大空间、可持续、可投资。
- `cyclical`：主要由价格、库存或临时供给冲击驱动。
- `mature`：终局空间有限或渗透率已高。
- `uncertain`：空间可能很大，但兑现时间或商业模式无法验证。

### 4.2 月度领先指标层

只监控用户批准的结构性主题。每个主题在 `theme_registry.yaml` 中注册3-6个行业专属指标，优先覆盖两个以上独立类别：

- 需求：销量、装机、渗透率、吞吐量。
- 订单：招标额、在手订单、合同负债。
- 供给：产能利用率、有效运力、扩产周期、交期。
- 库存：渠道、厂商和关键原料库存。
- 价格：产品价格、原料价格、价差。
- 单位价值：产品代际、配置升级、价值量提升。
- 资本开支：客户预算、项目核准和执行进度。

每条观测写入：

```text
data/industry_research/cards/{theme_id}/indicator_history.jsonl
```

至少记录 `as_of_date`、`period_end`、`release_date`、`fetched_at`、真实数值、单位、来源和 `improving/stable/deteriorating/unknown`。月度雷达只读取不晚于研究截止日、且未超过新鲜度阈值的观测。

### 4.3 季度财务验证层

`shared_data_access.industry_financial_panel` 使用 `akshare.stock_yjbb_em` 获取全A业绩横截面，按东方财富行业聚合全部已披露公司。统计宇宙不使用也不扩充手工 `master_universe`。

计算指标：

- 营收增速中位数与正增长公司占比。
- 净利润增速中位数与正增长公司占比。
- 营收和利润同时正增长的公司数量与比例。
- 当前报告期相对上一连续报告期的营收/利润同比增速加速度。
- 营收和利润同时加速的公司数量与比例。
- 毛利率与ROE中位数。
- 按收入、利润和增长加速度排列的前三名公司代理。

同一报告期不能做“相比一个月前改善”比较，因为财报不是月频数据。正确比较是相邻报告期的同比增速是否继续加速。

### 4.4 单主题深研层

用户从月度基本面右侧候选中确认最多一个主题后，Agent研究：

1. 终端需求与TAM的悲观、基准、乐观公式。
2. 需求、供给、库存、价格、交期、资本开支和扩产周期。
3. 产业链各节点的供需约束、定价权和利润池方向。
4. 最受益节点的前三名公司及其市占率、业务纯度、客户、成本和产能。
5. 市值空间、状态迁移和可验证的证伪条件。

## 5. 状态机

产业状态只使用：

```text
observation
→ emerging
→ fundamental_right
→ expansion
→ overheated
→ downturn
→ archived
```

- `observation`：结构空间尚未确认。
- `emerging`：结构空间已确认，但领先指标尚未形成右侧共振。
- `fundamental_right`：至少两个独立类别的领先指标改善。
- `expansion`：领先指标继续改善，且财务扩散开始验证。
- `overheated`：供给集中扩张、估值透支或下游回报恶化。
- `downturn`：需求、订单、价格或库存证据持续转弱。
- `archived`：结构逻辑被证伪或研究价值消失。

状态是研究结论，不是自动交易指令。

## 6. 三层宇宙

```text
全A统计宇宙
→ 只做行业中位数、扩散宽度和龙头代理统计

结构候选宇宙
→ 半年扫描后由用户批准的10-20个产业主题

交易研究宇宙
→ 只有人工确认的公司才进入现有深研或交易流程
```

行业面板中的前三名不自动写入 `master_universe`。真正龙头必须在产业链深研中核验，避免把“规模大”误当成“最受益”。


## 9. 时间因果与数据滞后

AkShare本身是数据接口聚合层，数据是否滞后取决于原始数据的发布频率：

- 申万行业目录适合半年级全行业建图，不承担景气判断。
- 财报天然滞后一个季度左右，只适合验证增长扩散。
- 月度销量、装机、招标、排产和库存适合确认产业拐点。
- 周度价格、运价或交期可以作为月度汇总输入，但不因此把研究频率改为每日。
- TAM、渗透率、技术路线、扩产周期和供需错配通常没有统一AkShare接口，需要Agent深搜原始材料。

抓取阶段面向真实当前时间获取足量数据，不按回测日期缩短窗口。历史复盘只在读取阶段按 `release_date <= as_of_date` 判断当时是否可见，不能用 `period_end` 代替发布日期。
