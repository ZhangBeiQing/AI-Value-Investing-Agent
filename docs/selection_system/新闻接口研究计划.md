## 1. 目标

本研究计划服务于一期 `hot_news_state` 模块设计，目标不是立刻实现完整代码，而是先把“可用新闻源、可控成本、时效过滤、结构化落库、深度研究触发条件”研究清楚。

本计划重点回答 5 个问题：

1. AkShare 现有新闻/快讯接口能提供什么数据，哪些适合做日常低成本输入源。
2. BettaFish 中 Tavily、Anspire、Bocha 的搜索方式哪些值得迁移。
3. U 深搜和 U 深研适合放在系统的哪个层级，什么时候调用才划算。
4. `hot_news_state` 应该用什么更新机制，才能兼顾时效、成本和可解释性。
5. 一期最稳妥的“新闻输入分层架构”应该怎么搭。

## 3. 当前已确认事实

## 3.1 AkShare 接口层面

基于本地 `akshare` 已安装源码检查，当前已确认：

1. `stock_info_cjzc_em()`
   - 无参数
   - 来源：东方财富财经早餐
   - 返回列：`标题`、`摘要`、`发布时间`、`链接`
   - 特征：更像“每日早餐摘要”，适合作为宏观与市场总览输入

2. `stock_info_global_em()`
   - 无参数
   - 来源：东方财富全球财经快讯
   - 返回列：`标题`、`摘要`、`发布时间`、`链接`
   - 特征：快讯型，适合作为全市场增量 feed

3. `stock_info_global_sina()`
   - 无参数
   - 来源：新浪财经全球快讯
   - 返回列：`时间`、`内容`
   - 特征：字段较简陋，缺少标题和链接，需要后处理清洗

4. `stock_info_global_futu()`
   - 无参数
   - 来源：富途快讯
   - 返回列：`标题`、`内容`、`发布时间`、`链接`
   - 特征：标准快讯 feed

5. `stock_info_global_ths()`
   - 无参数
   - 来源：同花顺财经直播
   - 返回列：`标题`、`内容`、`发布时间`、`链接`
   - 特征：标准快讯 feed

6. `stock_info_global_cls(symbol="全部"|"重点")`
   - 仅支持轻量筛选参数 `symbol`
   - 返回列：`标题`、`内容`、`发布日期`、`发布时间`
   - 特征：财联社电报，质量较高，适合重点新闻输入

7. `stock_news_em(symbol="603777")`
   - 输入单个股票代码
   - 返回列：`关键词`、`新闻标题`、`新闻内容`、`发布时间`、`文章来源`、`新闻链接`
   - 特征：个股级最近新闻，适合对 shortlist 股票补新闻

8. `stock_news_main_cx()`
   - 无参数
   - 返回列：`tag`、`summary`、`url`
   - 特征：更像精选新闻摘要，不是标准快讯流

### 3.2 AkShare 接口的限制

当前最关键的限制：

1. 上述多数接口都不支持直接传入起止日期。
2. 这些接口更像“拉取当前最新一页或几页内容”，不是“按历史窗口查询”。
3. 如果要做“过去一周热点”或“2 个月渐进式状态”，必须由我们自己做：
   - 定时抓取
   - 落库
   - 去重
   - 按发布时间过滤
   - 主题归并

这意味着 AkShare 更适合作为 `feed ingestion` 输入层，而不是历史查询层。

见：

- [search.py](/home/zhangbeiqing/programer/AI-Value-Investing-Agent/BettaFish/QueryEngine/tools/search.py)

2. 返回结构里保留 `published_date`，便于后续做时效过滤。

1. `comprehensive_search`
2. `search_last_24_hours`
3. `search_last_week`

其核心做法是通过：

1. `FromTime`
2. `ToTime`

显式控制时间范围。

这非常适合迁移到我们的项目，因为你已经明确提出“主动搜索时必须限定最近一周”。

### Bocha

同样见：

- [search.py](/home/zhangbeiqing/programer/AI-Value-Investing-Agent/BettaFish/MediaEngine/tools/search.py)

1. `comprehensive_search`
2. `web_search_only`
3. `search_for_structured_data`
4. `search_last_24_hours`
5. `search_last_week`

对我们的一期新闻系统来说，Bocha 不是首选，但其“结构化卡片能力”未来在宏观、指数、商品价格等场景可能有价值。

## 3.5 UniFuncs 的成本定位

基于你的使用反馈和当前目标，建议暂定如下定位：

1. U 深搜：
   - 只用于 shortlist 股票或重大主题的“深一层补研究”
   - 不进入全市场日更快扫主链

2. U 深研：
   - 只用于高价值、低频任务
   - 如季度财报深研、重大产业主题深研、极少数重点股票深研
   - 一期不应作为 `hot_news_state` 的常规输入源

## 4. 一期建议的新闻输入分层

建议将新闻输入源分成三层：

### 第一层：低成本稳定 feed

目标：每天稳定更新，成本接近零。

候选来源：

1. `stock_info_cjzc_em`
2. `stock_info_global_em`
3. `stock_info_global_ths`
4. `stock_info_global_cls`
5. `stock_news_em`（仅对 shortlist 股票调用）
6. 公告链路

用途：

1. 构建 `market_hot_state`
2. 构建 `symbol_event_state`
3. 形成每日增量事件流

### 第二层：受控主动搜索

目标：在规则层判断“值得搜索”时，再进行联网补充。

候选来源：

1. Tavily
2. Anspire

调用原则：

1. 默认只允许：
   - 最近 24 小时
   - 最近 1 周
   - 显式日期区间
2. 禁止无时间边界的泛化全网搜索作为默认路径

适用场景：

1. 主题需要补充背景
2. 某股票新闻过少但事件较重要
3. 宏观快讯需要做多源交叉验证

### 第三层：高成本深度研究

目标：只在高价值任务上使用。

候选来源：

1. U 深搜
2. U 深研

适用场景：

1. shortlist 股票深挖
2. 财报研究
3. 重大产业政策影响分析
4. 最终裁判前补高质量证据链

## 5. `hot_news_state` 推荐更新机制

一期建议采用“抓取增量 -> 标准化 -> 去重 -> 事件归并 -> 主题衰减”的状态机。

### 5.1 更新主流程

```text
Step 1. 拉取当日 feed
Step 2. 统一字段映射
Step 3. 生成标准 news_item
Step 4. 去重
Step 5. 归并到已有 theme/symbol state
Step 6. 更新热度与衰减
Step 7. 归档低热度旧主题
```

### 5.2 建议的标准化新闻结构

```json
{
  "source": "cls",
  "source_type": "telegraph",
  "title": "某行业迎来政策催化",
  "content": "......",
  "published_at": "2026-03-15 09:12:00",
  "url": "https://...",
  "symbol_candidates": ["600111.SH"],
  "theme_candidates": ["稀土", "资源品"],
  "importance_hint": 0.78,
  "dedupe_hash": "xxx"
}
```

### 5.3 为什么不建议“每天重新总结全文”

因为这样会导致：

1. 模型重复阅读旧信息
2. 无法跟踪主题衰减
3. 成本持续抬高
4. 结果不稳定，容易每天改写历史结论

更好的方式是：

1. 保留“结构化事件流”
2. 用主题状态做增量合并
3. 仅在输出给策略层时做轻量摘要

## 7. 低成本验证顺序

建议按以下顺序做验证，避免一开始就调用高成本接口：
