# 因子库与量化初筛系统设计

更新日期：2026-06-12

## 1. 设计目标

把「筛选」和「解释」分开：

```text
程序负责：统一因子、横截面排序、Top N 初筛、回测和换仓规则
AI 负责：对 Top N 候选做新闻 / 公告 / 财报 / 产业逻辑复核和最终决策
```

核心原则：

- 先用可复现、可回测的轻量因子从全宇宙筛出候选池
- 再对候选池补充较重的公告、新闻、筹码、资金流和财报材料
- 最后才让 AI 做短期 / 长期分组、排雷、入池理由和深研优先级

量化初筛的产物 `12_quant_prefilter_short.csv` 与 `12_quant_prefilter_long.csv` 是日常三账本主流程的直接输入：`run_daily_pipeline --all-books` 会在 `08_short_book_candidates.json` / `09_long_book_candidates.json` 不存在时直接回退到这两个 CSV 作为 short_book / long_book 的股票来源。

## 2. 数据分层

### 2.1 Raw Dataset：原始数据缓存

Raw Dataset 是外部事实，来自 akshare、巨潮、交易所、模型解析后的公告原文等。由 `shared_data_access` 统一管理。

典型数据：

- `prices/price.csv`：开高低收、成交量、成交额、换手率
- `financials_cache/*.csv`：利润表、资产负债表、现金流、财务摘要
- `share_info/*.csv`：股本、流通股本、股本变动
- `disclosures/`：公告列表、PDF、Markdown、索引
- `chip_distribution/chip_distribution.csv`：筹码分布
- `data/global_cache/board_metrics_ths/`：板块行情与板块历史
- `data/global_cache/macro_objective_panel/`：宏观客观面板
- 大单资金、主力资金流（按需补缓存）

Raw Dataset 的职责：

- 外部抓取
- TTL 和刷新策略
- 缓存目录和元数据
- 抓取失败重试和降级
- 读取时按 `as_of_date` 做时间截断

抓取阶段面向真实当前时间拿足历史，不用 `as_of_date` 裁剪抓取窗口；回测或复盘只在读取阶段裁剪。

### 2.2 Derived Factor：衍生因子

Derived Factor 是从 Raw Dataset 计算出来的特征，不直接负责外部抓取。由 `services/selection_system/factor_store.py` 与 `factor_history.py` 统一生成。

典型因子：

- RSI、MACD、MA5/10/20/60、均线多头排列、价格相对均线距离
- 3/6/12 月收益、夏普、最大回撤、近 20/60 日波动率
- PE、PB、PS、PEG、PE/PB 历史分位、当前价所处历史价格区间
- ROE、毛利率、净利率、营收增速、净利润增速、扣非净利润增速
- 放量突破、缩量回调、52 周高点距离
- 3.5 年内最高价格、最低价格、价格分布分位
- 公告关键词命中：回购、增持、分红、订单、中标、预增、减持、质押、问询、立案
- 板块热度、主题命中
- 筹码派生指标：获利盘比例、成本集中度、当前价相对筹码峰位置、上方套牢压力
- 资金派生指标：主力净流入分位、大单净额分位、资金连续性

Derived Factor 的职责：

- 从 `shared_data_access` 或现有缓存读取原始数据
- 按 `as_of_date` 截断后计算
- 写入统一的因子库 `data/factor_store/`
- 给选股、回测、AI 输入共用

## 3. Factor Store：统一因子库

`data/factor_store/` 是独立于 `basic_info_cache` 的统一因子库。

`basic_info_cache` 继续作为基础快照来源之一；`factor_store` 把多个来源汇总后生成统一因子宽表。

目录结构：

```text
data/factor_store/
├── manifest.json              # 最近构建日期、字段版本、来源版本
├── factor_registry.json       # 因子注册信息
├── history_manifest.json
├── by_symbol/
│   ├── 000063.SZ.csv
│   ├── 000063.SZ.parquet
│   ├── 600406.SH.csv
│   └── 600406.SH.parquet
└── by_date/
    ├── 2026-06-11.csv
    └── 2026-06-11.parquet
```

设计要求：

- `parquet` 给程序、回测、模型读取
- `csv` 给人用 VSCode、Excel、命令行快速检查
- `manifest.json` 记录最近构建日期、字段版本、因子 schema 版本、来源版本

### 3.1 by_symbol：单股纵向视图

一行 = 某只股票在某一天的全部因子：

```text
date, symbol, stock_name, pe_ttm, pb, peg, roe, rsi_14, macd,
ma5, ma20, ma60, ma_bullish_score, chip_profit_ratio, money_flow_score, ...
```

用途：

- 查看单只股票历史因子变化
- 支持增量更新，每天追加或覆盖最新一行
- 支持回测按股票读取历史序列
- 支持调试某只股票为什么进入或退出候选池

### 3.2 by_date：当日横截面视图

一行 = 当天某只股票的全部因子，全表 = 当天全市场因子横截面。

同一份横向快照同时导出到选股运行目录：

```text
data/selection_runs/YYYY-MM-DD/12_factor_snapshot.csv
data/selection_runs/YYYY-MM-DD/12_factor_snapshot.json
```

用途：

- 当天横截面排序
- 生成短期 / 长期 Top N
- 给 AI 读取和人工检查
- 固化每日选股输入，方便之后复盘

### 3.3 因子注册

所有因子注册在 `services/selection_system/factor_registry.py`，每个因子至少记录：

```text
factor_name: pe_percentile_3_5y
group: valuation
direction: lower_better
horizon: long
source: pe_pb_analysis_json
source_type: derived
cost_tier: light
point_in_time: true
transform: cross_section_rank
missing_policy: neutral
default_weight_short: 0.00
default_weight_long: 0.08
```

字段说明：

- `group`：`valuation` / `fundamental` / `trend` / `technical` / `liquidity` / `volatility` / `event` / `board` / `money_flow` / `chip` / `risk`
- `direction`：`higher_better` / `lower_better` / `neutral` / `range_best`
- `horizon`：`short` / `long` / `both`
- `source_type`：`raw` / `derived`
- `cost_tier`：`light` / `medium` / `heavy`
- `point_in_time`：是否满足回测时间因果
- `missing_policy`：`neutral` / `penalty` / `drop` / `forward_fill`

因子成本分层：

- `light`：每天全宇宙可跑，比如价格、估值、技术、流动性、板块热度、主题命中、资金流、筹码分布
- `medium`：适合 Top N 或缓存稳定后全宇宙跑
- `heavy`：只对候选池跑，比如财报 PDF 深读、新闻语义总结、AI 逐股研究

## 5. 评分模型

短期和长期是两种策略，分别生成：

```text
short_score
long_score
```

`combined_score` 仅用于兼容「单个 TopN 列表」和去重展示，**不**用于因子有效性验证、参数搜索或正式回测。

### 5.1 短期分

短期池更关注 1 到 20 个交易日的表现，重点是趋势、量价、资金、板块和事件。

初始权重建议：

```text
trend_score: 25%
technical_score: 20%
liquidity_score: 15%
volatility_breakout_score: 15%
money_chip_score: 15%
event_board_score: 10%
valuation_score: 仅作风险约束，不作为主权重
```

短期池的估值不宜权重太高，否则牛市强势股容易被过早过滤。但估值极端、上方套牢压力极大或明显财报风险，应进入扣分项。

### 5.2 长期分

长期池更关注 20 到 250 个交易日的表现，重点是质量、增长、估值赔率和回撤控制。

初始权重建议：

```text
quality_score: 30%
valuation_score: 25%
growth_score: 20%
trend_confirmation_score: 10%
risk_drawdown_score: 10%
event_governance_score: 5%
```

长期池不追求每天换最强票，而是寻找质量、估值、增长和趋势都能站得住的股票。

### 5.3 配置化评分层

评分逻辑由：

```text
configs/selection_system/factor_scoring.yaml
services/selection_system/factor_scoring.py
```

负责：

- `factors`：声明每个原始因子的方向（`higher_better` / `lower_better` / `range_best`）；支持 `type_configs` 按 `stock_type` 改写方向和区间评分
- `score_groups`：声明每个主维度内部的子因子权重（`valuation_score` / `quality_score` / `growth_score` / `chip_score` 等）；支持 `type_weights` 按股票类型配置完全不同的子因子权重
- `quality_score` 只表达商业模式和盈利质量（ROE、毛利率、净利率）；`growth_score` 单独表达营收、净利润、扣非净利润增速，避免成长指标在长期分里重复计权
- `valuation_score` 按 `stock_type` 使用不同子权重：成长股主要看 PEG/PE 历史相对位置，周期股主要看 PB 历史相对位置，特殊股只保留价格位置类参考
- `short.main_weights` / `long.main_weights`：声明短期分和长期分的大维度权重；`long.main_weights` 支持 `type_weights`
- `short.gates` / `long.gates`：声明硬过滤规则，失败原因写入 `short_exclude_reason` / `long_exclude_reason` / `exclude_reason`
- `long.type_gates`：按 `stock_type ∈ {growth, cyclical, special}` 使用不同长期门槛

股票类型字段在 `master_universe.json` 的 stock 条目里：

```json
{
  "symbol": "600406.SH",
  "name": "国电南瑞",
  "sector": "科技",
  "industry": "电网自动化",
  "stock_type": "growth"
}
```

当前长期门槛口径：

- `growth`：使用 PE 有效性、PEG 门槛；不再用 `pe_3_5y_percentile` 或单期 ROE 做硬过滤，ROE 只作为质量分子因子参与排序
- `cyclical`：使用 PB 有效性、`pb_3_5y_percentile` 门槛
- `special`：不设置硬门槛，只参与正常打分排序

估值分数口径：

- 不再把 `pe_ttm` / `pb` / `ps` 这种绝对估值倍数直接放进统一 `valuation_score`，因为不同行业长期合理估值区间差异很大
- `growth`：使用 `peg` / `pe_3_5y_percentile` / `pe_current_vs_median` + 价格位置类因子
- `cyclical`：使用 `pb_3_5y_percentile` / `pb_current_vs_median` + 价格位置类因子
- `special`：暂时只使用价格位置类因子，避免用 PE/PB/PEG 错杀早期或未盈利公司

### 5.4 标准化和缺失处理

横截面 rank 归一化：

```text
higher_better: percentile_rank(value)
lower_better: 1 - percentile_rank(value)
range_best: 距离目标区间越近越高
```

缺失值处理：

- 轻量因子缺失：给中性分 `0.5`
- 关键因子缺失过多：降低该股票 `data_quality_score`
- 外部事件因子缺失：默认无事件，不直接扣分
- 财务关键字段缺失：长期分降权或剔除
- `pe_ttm <= 0` 不代表便宜，而代表当前盈利为负或估值不可比；此时 PE 相关分位、PEG 和 PE/中位数不参与估值打分，只保留原始 `pe_ttm` 供人工识别亏损状态

## 6. Top N 与换仓规则

评分只负责排序，正式入池不机械全替换。

### 6.1 初筛候选

```text
Top20 总候选
short_top20
long_top20
```

AI 或规则层再从中形成：

```text
short_book: 7 只（按 short_book skill 当前规则上限）
long_book: 10 只
```

### 6.2 短期池换仓

- 正式池上限 7 只，候补池 Top8 到 Top20
- 每日最多替换 2 到 3 只
- 旧票仍在 Top15，可默认保留
- 新票要比池内末位高 5% 到 10% 的分数差，才允许替换
- 强制出池条件：跌出 Top20、催化证伪、放量破位、持有超过 20 个交易日

### 6.3 长期池换仓

- 正式池上限 10 只，候补池 Top11 到 Top20
- 每周最多替换 1 到 2 只
- 旧票仍在 Top20，且基本面没有恶化，默认保留
- 新票必须显著优于池内末位，并说明替换哪只旧票
- 强制出池条件：财报恶化、核心逻辑证伪、估值极端泡沫、连续多日跌出 Top30
- **已持仓的股票**（`data/agent_data/book-long_book/position/position.jsonl` 中存在）今日不得从 long_book 候选结果中剔除，只能保留并调整优先级或风险表述

## 7. 命令入口

### 7.1 当天主链路（由 `refresh_all_for_date.py` 自动串联）

```bash
python scripts/manage_selection_system.py build-factor-store --date YYYY-MM-DD
python scripts/manage_selection_system.py build-factor-scores --date YYYY-MM-DD
python scripts/manage_selection_system.py build-quant-prefilter --date YYYY-MM-DD
```

输出：

```text
data/factor_store/manifest.json
data/factor_store/by_symbol/{symbol}.{csv,parquet}
data/factor_store/by_date/{date}.{csv,parquet}
data/selection_runs/{date}/12_factor_snapshot.{csv,json}
data/selection_runs/{date}/13_factor_scores.{csv,json}
data/selection_runs/{date}/12_quant_prefilter.{csv,json}
data/selection_runs/{date}/12_quant_prefilter_short.csv
data/selection_runs/{date}/12_quant_prefilter_long.csv
```

### 7.2 历史补齐与回测

```bash
# 历史因子补齐（按股票批量构建，纯本地缓存）
python scripts/manage_selection_system.py build-factor-history \
  --source local_factor_store --start-date YYYY-MM-DD --end-date YYYY-MM-DD \
  --no-parquet --build-prefilter

# 仅基于已有 factor_store/by_date/* 补齐评分和初筛
python scripts/manage_selection_system.py build-factor-history \
  --source factor_store_cache --no-parquet --build-prefilter

# 量化初筛 TopN 等权前向回测
python scripts/manage_selection_system.py backtest-quant-prefilter \
  --score-column short_score --hold-days 1,3,5,10,20 \
  --start-date YYYY-MM-DD --end-date YYYY-MM-DD

python scripts/manage_selection_system.py backtest-quant-prefilter \
  --score-column long_score --hold-days 20,60,120,250 \
  --start-date YYYY-MM-DD --end-date YYYY-MM-DD
```

`build-factor-history` 的 `--source` 选项：

- `local_factor_store`（默认）：根据本地 `price.csv` 覆盖的交易日批量补齐 `factor_store/by_symbol`、`by_date`、`13_factor_scores` 和可选 `12_quant_prefilter`；只读本地缓存，不触发外部抓取
- `factor_store_cache`：只读取已经存在的 `factor_store/by_date/*.csv`，用于在 raw 因子已经补齐后补生成 `13_factor_scores` 和 `12_quant_prefilter`，避免重复计算历史因子
- `computed_basic_info`：兼容路径，逐日调用 `basic_info` 生成基础快照，口径更贴近日常流水线但速度重很多，只适合少量日期验证或必要时重建
- `basic_info_cache`：只根据已经存在的 `basic_info_cache` 日期生成因子快照，适合检查旧缓存，不适合补齐 4 年历史

### 7.3 筹码分布刷新

```bash
# 全市场增量刷新
python scripts/manage_selection_system.py refresh-chip-distribution --date YYYY-MM-DD

# 单股强制刷新
python scripts/manage_selection_system.py refresh-chip-distribution \

# 全历史 CYQ 本地回算（用于历史回测）

  --prefer-local --full-history --force-refresh
```

## 8. 回测设计

回测分三层，不直接回测最终 AI 结论。

### 8.1 因子有效性回测

目标：验证单个因子或因子组是否有 alpha。

方法：

- 每日横截面分组：Top20% / 中间 / Bottom20%
- 计算不同持有期收益
- 检查 IC、Rank IC、分组收益、最大回撤、胜率

建议持有期：

```text
短期：1 / 3 / 5 / 10 / 20 个交易日
长期：20 / 60 / 120 / 250 个交易日
```

### 8.2 评分模型回测

目标：验证 `short_score` 和 `long_score` 的组合收益。

短期评估：

- Top10、Top20 等权
- 持有 1/3/5/10/20 个交易日
- 加入每日最多替换 2 到 3 只的换仓约束

长期评估：

- Top10、Top20 等权
- 持有 20/60/120/250 个交易日
- 加入每周最多替换 1 到 2 只、Top20 缓冲保留的约束

### 8.3 AI 复核前向跟踪

AI 复核层不能严格历史回测，因为它依赖新闻语义、联网搜索和当时上下文。

处理方式：

- 每天固化 AI 输入和输出
- 记录 AI 从 Top20 中选择的 short10 / long10
- 前向跟踪 1/5/20/60/120 日表现
- 和纯量化 Top20、规则 short10、规则 long10 对比

### 8.4 当前回测状态

- `backtest-quant-prefilter` 基于 `factor_store/by_date/*.csv` 做 TopN 等权前向收益验证
- 默认 `score_column=short_score`；长期回测必须显式传 `--score-column long_score`
- 不使用 `combined_score` 评估因子有效性，也不使用 `combined_score` 搜索参数
- 换仓约束回测仍未实现，后续需要在当前 TopN 等权回测之上加入短期每日最多替换 2-3 只、长期每周最多替换 1-2 只的组合状态机

## 9. 与现有系统的关系

- `basic_info_cache`：保留作为 `factor_store` 的数据来源之一，**不**继续无限扩字段
- `analysis/technical_indicators_YYYYMMDD.csv` 和股票分析报告：保留，作为 MACD、RSI、MA、成交额、换手率等技术因子的来源
- `pe_pb_analysis/*.json`：保留，作为 PEG、历史 PE/PB、价格区间、历史极值等估值因子的来源
- `12_quant_prefilter_short/long.csv` 直接作为 `run_daily_pipeline --all-books` 的 short_book / long_book 输入来源（在 `08/09` 候选 JSON 不存在时回退到这两个 CSV）
- AI 选股 skill（`auto-selection-daily-pipeline`）仍可用于生成 `07/08/09/10/11` 文件，但日常默认不跑——量化初筛直接驱动三账本是当前主路径

## 10. 关键设计结论

- `shared_data_access` 管原始数据
- factor engine 算衍生因子
- `factor_store` 存统一因子宽表
- by_symbol 是纵向视图，看单股随时间变化
- by_date 是横向视图，看某天全股票对比
- `selection_runs/{date}/12_factor_snapshot.*` 是当天选股和 AI 输入的快照
- 评分分短期和长期，不共用一个总分
- 回测先测量化层，不直接回测 AI 联网判断
- AI 从全宇宙筛选器降级为 Top N 复核器，并由三账本 skill 各自承担最终决策
