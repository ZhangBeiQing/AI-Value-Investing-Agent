# 板块热度摘要与查询设计

更新日期：2026-06-12

## 1. 目标

回答两类问题，且都不能让 AI 整份读取全市场板块快照：

1. 「今天市场重点在交易哪些板块」
2. 「某主题对应的板块最近是否被资金确认」

为此提供两层结构：

1. 当日入榜板块研究结果：`05_board_heat_state.json`
2. 板块层全局导航摘要：`05_board_heat_digest.json`
3. 单板块按需查询：`scripts/query_board_snapshot.py`

底层全市场板块快照（`data/global_cache/board_metrics_ths/`）不直接塞进 AI 上下文。

## 2. 文件契约

### 2.1 `data/selection_runs/YYYY-MM-DD/05_board_heat_state.json`

当日入榜板块的研究结果（结合涨/跌幅榜 + 量化快照 + 模型研究）。字段定义详见同目录 `05_board_heat_state字段说明.md`。

由 `services/selection_system/board_heat.py` 生成，CLI 入口：

```bash
python scripts/manage_selection_system.py build-board-heat-state --date YYYY-MM-DD
```

### 2.2 `data/selection_runs/YYYY-MM-DD/05_board_heat_digest.json`

板块层全局导航，给 AI 一次性读取，控制上下文体积。

```json
{
  "run_date": "2026-06-11",
  "generated_at": "2026-06-11T21:50:00",
  "summary": {
    "board_count": 90
  },
  "top_boards_today_by_change_pct": [],
  "top_boards_today_by_breadth": [],
  "top_boards_recent_by_5d_rank": [],
  "top_boards_recent_by_20d_rank": []
}
```

每个榜单元素只保留：

- `rank`
- `board_name`
- 当前榜单对应的关键数值

不放：

- 板块成分股
- 大段研究文本
- 完整量化字典

### 2.3 单板块按需查询

```bash
python scripts/query_board_snapshot.py \
  --date 2026-06-11 \
  --board-name "通信设备" \
  --board-name "半导体"
```

`--board-name` 支持重复传入。输出是单板块精简结果列表，不返回整份 `market_snapshot` 或 `daily_snapshot` 原文。每个板块仅返回三类字段：

1. `today` — 当日盘口强弱
2. `trend` — 近 3/5/10/20 日强弱和排名
3. `structure` — 宽度、龙头偏离、阶段位置

## 3. 名称标准化规则

### 3.1 为什么不用 `board_code`

渐进式新闻总结应保持简洁，不把 `board_code` 写进每个主题。

因此：

1. `linked_boards` 继续只保留板块名
2. 标准化通过 skill 输入约定里的固定标准板块名清单实现
3. 查询阶段由本地脚本做精确匹配和保守模糊匹配

### 3.2 `linked_boards` 约束

1. 优先使用 skill 输入约定中的标准板块名清单
2. 不要优先写别名、口语词或主题词
3. 不确定时宁可少写，不要编造

## 4. AI 使用方式

`gradual-hot-news-summary` skill 中，AI 按以下顺序使用板块数据：

1. 读 `05_board_heat_digest.json`
2. 用 skill 输入约定中的标准板块名清单约束 `linked_boards`
3. 若某主题需要更细板块证据，再调用 `query_board_snapshot.py`
4. **不**直接整份读取 `daily_snapshots` 或 `market_snapshots`
