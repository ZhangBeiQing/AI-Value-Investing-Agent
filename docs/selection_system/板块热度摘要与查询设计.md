# 板块热度摘要与查询设计

更新日期：2026-04-03

## 目标

解决两个问题：

1. `05_board_heat_state.json` 只覆盖当日入榜板块，不足以支撑渐进式新闻总结判断“某主题关联板块最近是否继续确认”
2. `data/global_cache/board_metrics_ths/daily_snapshots/YYYY-MM-DD.json` 和 `market_snapshots/YYYY-MM-DD.json` 是全市场数据，但体积大，不适合整份塞进模型上下文

因此补一层：

1. 小型摘要文件，给 AI 全量读取
2. 单板块查询脚本，给 AI 按需读取

## 现状

### `05_board_heat_state.json`

- 定位：当日入榜板块的研究结果
- 优点：适合回答“今天市场重点在交易哪些板块”
- 缺点：没有覆盖全市场所有板块，不能直接用于主题级连续跟踪

### `market_snapshots/YYYY-MM-DD.json`

- 定位：全市场板块当日盘口横截面
- 主要字段：
  - `change_pct`
  - `up_count`
  - `down_count`
  - `total_turnover`
  - `leading_stock_name`
  - `leading_stock_change_pct`

### `daily_snapshots/YYYY-MM-DD.json`

- 定位：全市场板块量化日快照
- 包含：
  - 当日盘口字段
  - 多窗口收益和排名
  - 连涨连跌和强势频次
  - 宽度和阶段指标

## 新增文件

### `data/selection_runs/YYYY-MM-DD/05_board_heat_digest.json`

用途：

1. 给 AI 提供板块层全局导航
2. 控制上下文大小
3. 提供近期板块热点排序概览

建议结构：

```json
{
  "run_date": "2026-04-03",
  "generated_at": "2026-04-03T21:50:00",
  "summary": {
    "board_count": 90
  },
  "top_boards_today_by_change_pct": [],
  "top_boards_today_by_breadth": [],
  "top_boards_recent_by_5d_rank": [],
  "top_boards_recent_by_20d_rank": []
}
```

每个榜单元素保持极简，只保留：

1. `rank`
2. `board_name`
3. 当前榜单对应的关键数值

不放：

1. 板块成分股
2. 大段研究文本
3. 完整量化字典

## 查询脚本

### `scripts/query_board_snapshot.py`

参数保持最少：

1. `--date YYYY-MM-DD`
2. `--board-name 板块名`

`--board-name` 支持重复传入多次。

示例：

```bash
python scripts/query_board_snapshot.py \
  --date 2026-04-03 \
  --board-name "通信设备" \
  --board-name "半导体"
```

输出是单板块精简结果列表，不返回整份 `market_snapshot` 或 `daily_snapshot` 原文。

建议每个板块仅返回三类字段：

1. `today`
   - 当日盘口强弱
2. `trend`
   - 近 3/5/10/20 日强弱和排名
3. `structure`
   - 宽度、龙头偏离、阶段位置

## 名称标准化规则

### 为什么不用 `board_code`

当前渐进式新闻总结输出应保持简洁，不把 `board_code` 写进每个主题。

因此：

1. `linked_boards` 继续只保留板块名
2. 标准化通过 skill 输入约定里的固定标准板块名清单实现
3. 查询阶段由本地脚本做精确匹配和保守模糊匹配

### `linked_boards` 约束

1. 优先使用 skill 输入约定中的标准板块名清单
2. 不要优先写别名、口语词或主题词
3. 不确定时宁可少写，不要编造

## AI 使用方式

渐进式新闻 skill 中，AI 应按以下顺序读：

1. 读 `05_board_heat_digest.json`
2. 用 skill 输入约定中的标准板块名清单约束 `linked_boards`
3. 若某主题需要更细板块证据，再调用 `query_board_snapshot.py`
4. 不直接整份读取 `daily_snapshots` 或 `market_snapshots`
